# 排版规范细则（字号/配色/边框）

> SKILL.md 第一节给的是速查表，本文给的是判据、理由与边界情况。
> 规范正本：资料库《公众号开发环境与排版规范》第五、六章 +《公众号排版参数（落地方案）》。

---

## 一、字号：为什么是 16px

| 字号 | 适配| 适用场景 |
|---|---|---|
| 14px | 精致路线 | 情感、文艺类；文字量大的干货文也能容纳更多信息 |
| 15px | 万能默认 | 适配多数场景，拿不准就用它 |
| **16px** | 清晰路线 | **资讯、科普类长文；中老年读者占比高的账号** |

**本号定位技术科普 + 实操干货，正文统一 16px。**

字体：公众号后台默认微软雅黑（Windows）/ 苹方（Mac），**原生不支持更换**。
一篇文章字体**不超过两种**。

---

## 二、行距与留白

| 项 | 值 | 说明 |
|---|---|---|
| **行距** | **1.75** | 通用舒适值，既不拥挤也不松散 |
| 段间距 | 22px（margin-bottom） | 空一行，无需首行缩进 |
| 字间距 | 0.5px / 1px | 干货短稿 0.5px，长技术文 1px，**上限 2px** |
| 两端边距 | 10px（section padding） | 左右各留白由 padding 控制 |

**行距换算**：16px × 1.75 ≈ 28px 行间距，符合人眼阅读习惯。
（若用 px 直写：16px 字号对应 24-28.8px 行间距）

> **⛔ 不要逐段调行距** —— 1.75 是全篇统一值。混用行距会让版面节奏碎掉。

---

## 三、结构习惯

1. 每段控制在 **3-5 行**就分段，避免「文字墙」
2. 一段最多加粗 **1-2 个关键词**，别通篇狂加粗
3. 重点用加粗或引用样式突出，**不要靠颜色堆砌**
4. **发布前提醒用户在手机真机预览** —— 不同设备对字号行距呈现有差异

> 第4 条是硬要求：⛔ 不要替用户判断真机效果，必须让他自己看。

## 四、配色：绿蓝双主色的分工

### 主色板

| 角色 | 字色 | 边条色 | 用途 |
|---|---|---|---|
| 正文 | `#3F3F3F` | — | 所有段落 |
| 小标题蓝 | `#2B77BF` | 左 4px `#2B77BF` | h2、表头、结构标识 |
| 分层绿 | `#046B27` | 左 4px `#09B83E` | 分层绿、文末绿卡 |
| 转折警示红 | `#A8281A` | 左 4px `#D93F2B` | 强转折句，全文 1-2 处 |
| 场景标签橙 | `#8A5A0B` | 左 4px `#E8A33D` | 场景标签，3 处以内 |

### 浅底（由主色淡化，**不新增色相**）

| 用途 | 色值 |
|---|---|
| 绿系浅底 | `#F0F9F2` |
| 蓝系浅底 | `#F4F8FC` |
| 红系浅底 | `#FDF3F2` |
| 橙系浅底 | `#FFF8EC` |
| 中性浅底 | `#F7F9FA` |
| 边框灰 | `#E3E8EF` |
| 注释灰 | `#7C8798` |
| 代码底 / 代码字 | `#282C34` / `#E4E6EB` |

### 六条规则

1. **提示词、代码、命令行一律 CLI 黑底** `#282C34` —— 它们是「可复制的东西」，视觉上必须跟说明性内容区分开
2. **表格归蓝色系**（表头 `#2B77BF` 底白字）
3. **三色分工不越界**（2026-10-13 定版，见下表）
4. **金句红是红色** `#FDF3F2`，**居中绿是绿底** `#F0F9F2` —— 别搞反
5. **红色仅用于提醒类语义**（金句/警示/重点提醒/文末①），橙色仅用于场景标签
6. **红色用得越少越有力**，满篇红反而失去视觉冲击

### 三色分工表（⛔ 高频错处）

| 版式 | 正确底色 | ⛔ 常见错法 |
|---|---|---|
| **金句 / 强调** | **`#FDF3F2` 红** | 误用绿底 / 蓝底 |
| 警示 / 封面警示卡 | `#FDF3F2` 红 | 2px 边框写成 1px |
| **升华 / 收尾** | **`#F0F9F2` 绿** | 误用红底 / 蓝底 |
| 分层 / 归类 · 报头 / 文末引导 | `#F0F9F2` 绿 | 误用蓝底 |
| 导语 / 规格 | `#F4F8FC` 浅蓝 | 误用绿底 |
| 导语（正文） | **蓝色 `#2B77BF`** | 正文写成深灰 |

> 历史上金句被做成绿底，肉眼很难发现，靠 `scripts/typeset_check.py` 的 B6 兜住。

> **实测结论（重要）**：绿+蓝双主色比单色方案好看。
> 曾按「三色定律 + 禁绿」的方案改过一版，用户反馈不如原版，已回退。
> **不要再改成单色方案。**

## 五、唯一一套样式的配色分配

⛔ **只有一套样式——悬浮。** 简报 / 长文 / 观点文只是**卡片密度与字数不同**，配色规则完全一样。
下面按区块列出配色，这是「整套怎么配」，不是可拆开挑用的零件清单。

| 区块 | 底色 | 文字 | 边框 |
|---|---|---|---|
| 底板 | `#F2F3F5` | — | ⛔ 无（合法例外） |
| 报头 | `#F0F9F2` | 标题 `#046B27` | **2px** `#09B83E` |
| 导语 | `#F4F8FC` | **正文 `#2B77BF`** | ⛔ **无边框**（刻意，见合法例外） |
| 栏目标 | `#FFFFFF` | `#046B27`，序号 `#09B83E` | 1px `#E3E8EF`，**20px** 胶囊 |
| 白卡（论述/资讯） | `#FFFFFF` | 标题 `#2B77BF` | 1px `#E3E8EF` |
| 绿卡（分层） | `#F0F9F2` | 标题 `#046B27` | 1px + 左 4px `#09B83E` |
| 红卡（金句） | **`#FDF3F2`** | `#A8281A` | 1px + 左 4px `#D93F2B` |
| 蓝卡（规格） | `#F4F8FC` | 标题 `#2B77BF` | 1px `#E3E8EF` |
| 提醒卡 | `#FDF3F2` | `#A8281A` | 1px `#E3E8EF` |
| 升华 | `#F0F9F2` | `#046B27` | 1px `#E3E8EF`，18px 居中 |
| **事实来源** | `#FFFFFF` | 标题 `#2B77BF` | 1px `#E3E8EF`（**内容级**） |
| 文末①最值得深挖 | `#FDF3F2` | `#A8281A` | **2px** `#D93F2B` |
| 文末③开源仓库 | `#F0F9F2` | `#046B27` | **2px** `#09B83E` |
| 文末④AI 对话 | `#F0F9F2` | `#046B27` | **2px** `#09B83E`，全篇最后一块 |
| 代码块（可选） | `#282C34` | `#E4E6EB` | ⛔ 无（合法例外） |
| 数据表（可选） | 表头 `#2B77BF` | `#FFFFFF` | 外框 `#E3E8EF`，**6px** 圆角 |

**红底配额（随字数伸缩，B7 强制）**：≤500字→1 张 · ≤1000字→2 张 · ≤2000字→3 张 · >2000字→4 张

**卡片密度（随字数伸缩）**：卡片数 = 字数 ÷ 150，取整，最少 2 张

### 悬浮形态

圆角 **12px** + 阴影 `0 2px 10px rgba(31,45,61,0.08)` + 内边距 18/20px。
数据表（6px 圆角，无阴影）与代码块（6px 圆角，黑底）**不是**这个形态。

## 六、边框体系（现行定版）

### 三档

| 档 | 用在哪 | 值 |
|---|---|---|
| **2px 亮绿** | 封面性区块（文末引导卡） | `border: 2px solid #09B83E` |
| **2px 红** | 提醒型卡（「本周最值得深挖」） | `border: 2px solid #D93F2B` |
| **1px 浅灰** | 正文内容区块（中间所有内容） | `border: 1px solid #E3E8EF` |

### 卡片统一造型

```
border-radius: 12px;
box-shadow: 0 2px 10px rgba(31,45,61,0.08);
```

### 最高优先级铁律

> **正文里每一个有底色的 `section`，都必须有 `border`。**

判据只有一条：**这个 section 有 `background` 吗？有 → 就必须有 `border`。**

必须按结构判角色，**绝不能靠"看着这篇文章有哪些卡片再逐个加"**。
本号已连续漏过 4 处：报头、导语、警示红卡、栏目标。

### 合法例外

| 元素 | 原因 |
|---|---|
| **导读块** | **刻意无边框**——底色 `#F4F8FC` 本身已足够分隔，加边框反而显脏 |
| 升华块 | 绿底 + 1px，属内容级收尾 |
| `#F2F3F5` 灰底托盘 | 承载整篇的背景容器，不是卡片 |
| `#282C34` 代码块黑底 | 功能性色，不参与卡片体系 |

### 判据坑（都踩过）

- ⛔ 不要用 `grep 'background:...;border'` 判断 —— 会误匹配 `border-radius: 20px`
- ⛔ 定位漏网行要用 `grep -v 'border:'`（**带冒号**）—— 只写 `'border'` 会连 `border-radius` 一起滤掉，列表永远为空
- ⚠️ shell 版按**行**计数，同一行多个 `<section>` 会与实际元素数对不上 —— **精确需求一律用 `scripts/typeset_check.py`（按元素计数）**

## 七、微信 HTML 硬约束

| 约束 | 原因 |
|---|---|
| **所有样式必须内联** `style="..."` | 微信会过滤 `<style>` 标签 |
| **不要用 class 属性** | 微信不保留 |
| 不使用 `<script>`、`onclick` | 安全策略 |
| 标签必须配对且嵌套正确 | 错位会导致微信渲染错乱 |
| 正文图片仅 `mmbiz.qpic.cn` | 外部图片必须先上传素材库 |
| 外链仅 `mp.weixin.qq.com` | 其他域名可能被拦 |

> 微信实测保留 `<a href="mp.weixin.qq.com/..."><img></a>`（图片可点），
> 但会把短链改写成 `?__biz=...&mid=...&sn=...` 长链，**这是正常的**，不是 bug。

## 八、封面图

- 标准头图比例 **2.35:1**（900×383），JPEG q92
- **AI 生成图通常带「AI生成」水印**，必须用 Pillow 裁掉底部约 8%
- 裁切要**小幅度试**：主体是三层结构时裁多了会切掉底层
- 主体偏左时，生成 prompt 里加「画面完全居中构图，左右留白均衡」

```python
from PIL import Image
im = Image.open(src).convert('RGB')
W, H = im.size
im2 = im.crop((0, int(H*0.03), W, int(H*0.92)))
im2 = im2.resize((900, 383), Image.LANCZOS)
im2.save('cover_900x383.jpg', 'JPEG', quality=92, optimize=True)
```

## 九、换品牌色时

只改两处：

1. 小标题色 → 换品牌主色
2. 强调色 → 选品牌色的补色（对比度 ≥3:1）

**代码黑 `#282C34` 保持不变** —— 它是功能性色，不属于品牌调性。
边框灰、浅底色都是主色淡化而来，换主色时同步更新。
